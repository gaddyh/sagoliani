# ART IN CLAY — קטלוג מוצרים

אתר קטלוג עברי ו־RTL למוצרי ART IN CLAY. הקולקציה מציגה **רק צילומי מוצרים מוגמרים** המקושרים למוצר, רקע וציור; עד להוספת צילומים כאלה היא ריקה. העגלה נשמרת בדפדפן, והבקשה נשלחת לאפרת בוואטסאפ; בשליחה העגלה מתפנה מיד, ולצד קישור העגלה בכותרת העליונה יש כפתור לפינוי ידני של העגלה. אין שרת, מסד נתונים, תשלום באתר או אישור אוטומטי של הזמנה. אפרת מאשרת זמינות, מחיר ומשלוח, ואז שולחת בעצמה קישור PayBox עסקי ומוודאת שהתקבל תשלום.

הסטודיו הניסיוני (עורך הגרירה והסיבוב) עבר לעמוד ניהול בכתובת `/admin/studio` — זמין גם באתר החי, לא מקושר מהניווט של הלקוחות וחסום למנועי חיפוש.

## הרצה

```sh
npm ci
npm run dev
```

פתחו `http://127.0.0.1:5173/`. בנייה: `npm run build`. בדיקת חנות עם צילומי בדיקה המוזרקים לדפדפן בלבד: `npm run test:visual` לאחר הפעלת שרת הפיתוח.

**חיפוש ושיתוף:** `npm run build` מריץ בסופו את `scripts/prerender.mjs`, שכותב HTML מוכן ב־`dist/index.html`, יחד עם נתונים מובנים על העסק ועל מוצרים שפורסמו בלבד, `robots.txt` ו־`sitemap.xml`. תמונת השיתוף `public/og-image.jpg` נוצרת מהחוברת ב־`scripts/prepare_brochure.py`. הכתובת הקנונית היא `https://sagoliani.onrender.com/`; אם עוברים לדומיין אחר, הגדירו ב־Render את משתנה הסביבה `SITE_URL`.

## פרסום צילומי מוצרים מוגמרים

כל צורה או גודל הוא מוצר נפרד ב־`src/data/products.ts` (למשל `english-platter-straight` ו־`english-platter-oval`). לכל מוצר יש מערך `sizes` עם תווית ומחיר לכל מידה; כשיש יותר ממידה אחת מופיע בעמוד המוצר תפריט נפתח של מידות, והמידה שנבחרה קובעת את המחיר בשורת הרכישה, בשורה בעגלה ובהודעת ההזמנה (מידות שונות של אותו שילוב הן שורות נפרדות בעגלה). המידה אינה חלק ממבנה התמונות — היא אופציית תמחור בלבד. שדה `uses` אופציונלי בשורת המוצר מציג בעמוד המוצר שורת שימושים מופרדת ב־`|` (למשל ״מרק | סלטים | קינוחים״). צילומי המקור שהתקבלו בוואטסאפ נשמרים ב־`assets-source/whatsapp/` (מחוץ ל־git) עד לעיבוד.

**ייבוא תיקיות צילומים מסודרות:** תיקיות מקור בעברית (שם כלי + ציור + חומר, למשל `שי חיבוק סגול חלק`) נשמרות תחת `assets-source/products/` בלי שינוי שם, ואז מיובאות בפקודה אחת עם `scripts/import_product_photos.py` — הסקריפט ממיר את הצילומים הרשומים בלבד ל־WebP לנתיב `public/assets/products/<product-id>/<material>/<artwork-id>[-NN].webp` ומוסיף את רשומת `finishedVariants` בעצמו (הצילום הראשון ברשימה הוא התמונה הראשית; קבצים שלא צוינו נשארים במקורם ולא מפורסמים):

```sh
.venv/bin/python scripts/import_product_photos.py shay-bowl smooth purple-embrace "חיבוק סגול" \
  "assets-source/products/שי חיבוק סגול חלק" "קערה קרמית עם פרחי לבנדר.png" ...
```

דרוש מוצר קיים (`ProductId` + שורה ב־`products`); `--dry-run` מדפיס את התוכנית בלי לכתוב, `--update` מחליף רשומה קיימת ואת תמונותיה. כלי חדש (כל שם הוא סוג כלי אחיד — קערה, תבנית, מגש וכו׳) מקבל מוצר משלו; תיקיות נוספות של אותו כלי מתווספות כשילובים (חומר/ציור) לאותו מוצר. ידנית אפשר עדיין לשמור WebP בנתיב `public/assets/products/<product-id>/<smooth|speckled>/<artwork-id>.webp` — השתמשו במזהה המוצר **בדיוק** כפי שהוא מופיע בקוד. אם יש כמה זוויות של אותו שילוב, שמרו אותן יחד כ־`meadow-01.webp`, `meadow-02.webp` וכו׳. לדוגמה:

```text
public/assets/products/english-platter-straight/smooth/meadow-01.webp
public/assets/products/english-platter-straight/smooth/meadow-02.webp
public/assets/products/english-platter-straight/speckled/spring.webp
```

לאחר שמירת הקבצים הוסיפו **רשומה אחת לכל שילוב** כלי–חומר–ציור במערך `finishedVariants` ב־`src/data/products.ts`:

```ts
{
  id: 'english-platter-straight-smooth-meadow',
  productId: 'english-platter-straight',
  material: 'smooth',
  artworkId: 'meadow',
  artworkName: 'פרחי שדה',
  images: [
    '/assets/products/english-platter-straight/smooth/meadow-01.webp',
    '/assets/products/english-platter-straight/smooth/meadow-02.webp',
  ],
}
```

הערכים האפשריים ל־`material` הם `smooth` (חומר חלק) ו־`speckled` (חומר מנוקד) — אלו האפשרויות בכפתורי הרדיו בעמוד המוצר. `id` חייב להיות ייחודי ויציב: כל הזוויות שב־`images` שייכות לפריט **אחד** בסל, והצילום הראשון הוא התמונה הראשית בכרטיס ובסל. לשילוב עם צילום יחיד כותבים `images: ['/assets/products/.../spring.webp']`. התיקייה לבדה לא מספיקה: חייבים להוסיף רשומה ולוודא שהנתיבים תואמים לקבצים. בדקו שהצילום והמחיר מאושרים לפרסום לפני ההוספה. מוצר שאין לו לפחות שילוב אחד עם תמונה לא יופיע באתר. אם לחומר מסוים אין צילומים, בחירה בו תציג הודעה ולא תאפשר רכישה. **תמונות חוברת ו־AI אינן תמונות של מוצר מוגמר ואין לפרסם אותן ב־`finishedVariants`; הדמיות סטודיו שנוספות דרך כפתור ״הוספה לקטלוג״ הן המחשה בלבד של השילוב — עדיף להחליפן בצילום אמת של הפריט כשקיים.**

**סדר ותמונת כריסה בקולקציה:** סדר הכרטיסים הוא סדר השורות במערך `products`. תמונת הכריסה של מוצר (והשילוב שנבחר בפתיחתו) היא הרשומה הראשונה שלו ב־`finishedVariants` — הצילום הראשון שבה הוא הכריסה — אלא אם הוגדר בשורת המוצר השדה האופציונלי `coverVariantId` עם מזהה רשומה משלו — למשל `coverVariantId: 'shay-bowl-speckled'` — ואז היא קובעת את תמונת הכריסה, את ברירת המחדל בפתיחה וגם את התמונה בנתונים המובנים למנועי חיפוש. כשלחומר מסוים יש ציור אחד בלבד, בוחר הציורים מוסתר ומוצגות ישירות התצוגה הגדולה וזוויות הצילום.

הרשומות שפורסמו עד כה: **קערת שי** (`shay-bowl`) — כל הצילומים הקיימים של הכלי מאוגדים לשילוב אחד לכל חומר תחת השם ״מגוון ציורים״, ללא בוחר ציורים: בחומר חלק 4 צילומים (״חיבוק סגול״ ×4) ובחומר מנוקד 3 צילומים (״חיבוק סגול״ ×3); צילומי ״ריקוד ורוד״ הוסרו מהתצוגה, במידות קוטר 16 (78 ₪) וקוטר 20 (88 ₪); **מגש עירית** (`irit-platter`) — כל הצילומים מאוגדים לשילוב אחד לכל חומר, ללא בוחר ציורים: בחומר חלק 2 צילומים (״שדה פרחי בר״ ו״לחש ורוד״ — `pink_whisper`) ובחומר מנוקד 2 צילומים (155 ₪). כשלשילוב יש כמה ציורים מוסיפים `imageArtworkNames` — מערך שמות ציור המיושר לתמונות — ושם הציור של התמונה הנבחרת מוצג בשורת ההזמנה, נשמר בשורת העגלה (יחד עם התמונה הנבחרת) ונשלח בהודעת הוואטסאפ; **תבנית יעל** (`yael-bowl`) עם ״דק מן הדק״ (`lions-maw`) בחומר חלק ובחומר מנוקד (צילום אחד לכל חומר, קוטר 25 — 175 ₪); **קערת עומר** (`omer-bowl`) עם ״לחישת השדה״ (`field-whisper`) בחומר מנוקד בלבד (4 תמונות, קוטר 16 — 78 ₪ / קוטר 20 — 88 ₪); שילוב החומר החלק הוסר, ובחירת ״חלק״ מציגה הודעה שאין צילומים זמינים; **סט צלחות להגשה ״אבני נחל״** (`river-stones`) — מאוחד משלושה מוצרי גודל למוצר אחד עם מידות גדול (100 ₪) / בינוני (75 ₪) / קטן (50 ₪) — עם ״שדה פרחי בר״ (`wild-magic`) בחומר חלק (2 צילומים); **מגש אלה** (`ella-platter`) עם ״ריקוד בשדה״ (`field-dance`) בחומר חלק (2 צילומים, 155 ₪); **צלחת מיקה** (`mika-plate`) עם ״נגיעה סגולה״ (`purple-touch`) בחומר חלק (5 צילומים, 165 ₪); **צלחת גדי** (`gaddy-plate`) עם ״בשדה ירוק״ (`green-field`) בחומר מנוקד (5 תמונות, קוטר 25 — 145 ₪). צילומי המקור של קערת שי בעבודת היד ב־`assets-source/shay/` והשאר תחת `assets-source/products/`. צילום מעורב (קערה חלקה לפני קערה מנוקדת) נשאר במקורו ולא פורסם.

## הסטודיו — עמוד ניהול בכתובת `/admin/studio`

הסטודיו עבר מהעמוד הראשי לעמוד ניהול משלו: `/admin/studio`. העמוד זמין **גם בבנייה לייצור** (לא רק בפיתוח) בכתובת בלתי מקושרת מהאתר, ללא אימות — כל מי שמכיר את הכתובת יכול לעצב ולשלוח קישור הדמיה לאפרת. `scripts/prerender.mjs` כותב עותק סטטי ב־`dist/admin/studio/index.html` כדי שהקישור הישיר יעבוד בכל אחסון סטטי ללא כללי rewrite; העמוד מסומן `noindex` ו־`robots.txt` חוסם את `/admin`.

**הוספה לקטלוג מהסטודיו:** לצד כפתור ״הורד PNG״ יש כפתור **״הוספה לקטלוג״**. הוא פותח טופס עם תצוגה מוקטנת של ההדמיה: המוצר בחנות (ממולא מראש לפי מיפוי הכלי — קערות שי ממולאות ל־`shay-bowl`; כלים לא ממופים דורשים בחירת מוצר קיים או יצירת מוצר חדש עם מזהה, שם, תיאור ומידות/מחירים), המידה והמחיר מהמוצר, והחומר (ממולא משם הכלי: חלק/מנוקד). בלחיצה על ״הורדת ההדמיה והעתקת הרשומה״ האתר מוריד WebP ששמו כבר תואם לנתיב הקטלוג (`<מוצר>-<חומר>-<איור>.webp`) ומעתיק ללוח את רשומת `finishedVariants` המוכנה (וכן רשומת מוצר חדשה עם מידות ומחירים אם נוצר מוצר חדש). לפרסום מעבירים את הקובץ ל־`public/assets/products/<מוצר>/<חומר>/` (בלי שינוי שם), מדביקים את הרשומה ב־`src/data/products.ts`, ומבצעים commit ו־push — האתר סטטי ואין שרת, לכן הפרסום עובר דרך ה־repo. ההדמיה היא המחשה של השילוב ולא צילום מוצר מוגמר; עדיף להחליף בצילום אמת כשקיים.

**מיקום, גודל וסיבוב:** אין יותר כפתורי מיקום מוכנים; האיור מתחיל במרכז, גוררים אותו על הכלי, ושלב ״גודל וסיבוב״ כולל פקד ״גודל״ (60%–500% מגודל ברירת המחדל של הכלי), פקד ״סיבוב״ (עד 90° שמאלה או ימינה, עם כפתורי ↺ ↻ בקפיצות של 15°) ופקד **״עיקום״** (0%–100%) שקובע כמה הציור נעטף סביב הכלי: 0% משאיר את הציור שטוח, ו־100% מעקם אותו על פני הכלי כמו כדור הנראה מלמעלה (לכל כלי ברירת מחדל משלו — קערות 100%, המגש השטוח 35%). שלושתם נשמרים בכתובת (`size`, `rot`, `wrap`) ובמפתח השחזור, ו״מתחילים מחדש״ מאפס אותם. קישורים ישנים עם `preset=small` או `preset=offset` עדיין נפתחים במיקום שלהם. במנוע הרינדור הסיבוב נעשה על האיור השטוח לפני עיוות הכלי (`rotatedArtwork` ב־`composite.ts`), כך שהעיקום, המסכה והחסימה בגבול אזור הקישוט פועלים כרגיל. בקערות עמוקות מאוד זה קירוב: הסיבוב קודם לעיקום, ולא מחושב על פני המשטח עצמו.

**ציור על כל שטח הכלי:** המסכות של הכלים מכסות את מלוא הצללית הנראית של הכלי (שפה, דופן פנימית וצד חיצוני) ולא רק את מרכז הפתח — כמו המוצרים המוגמרים בפועל, שבהם הציור עוטף את הכלי. כדי לכסות קערה שלמה מגדילים את הציור ל־~430% ומעלה; ציור שגדול מאזור הקישוט ניתן לגרירה כך שמרכזו נע בכל תחום המסכה, וכך אפשר להצמיד אותו לצד או לתחתית. העיוות נשאר קירוב שטוח (עיקום ופרספקטיבה פרופורציונליים), לא הצמדה לקימור הפיזי של הדופן. המסכות הורחבו עם `scripts/widen_masks.py` (מחשב את הצללית מהצילום, מכווץ מעט פנימה ומרכך); הרצה שלו מחדש מחליפה את כל קובצי `*-mask.png`.

**מבנה הסטודיו:** הסטודיו בנוי כעורך שתמיד נכנס במסך אחד, כך שאין צורך לגלול בין הבחירות לתוצאה. הבחירות באות לפני התוצאה: בטלפון הלשוניות (כלי, איור, גודל וסיבוב, סיכום) ושורת הבחירה נמצאות למעלה וההדמיה ממלאת את שאר המסך מתחתיהן; במחשב הפאנל מימין וההדמיה משמאל. בטלפון הכלים והאיורים מוצגים בשורה אחת שגוללים לצדדים. על ההדמיה: גרירה באצבע אחת מזיזה את האיור; בשתי אצבעות — צביטה משנה גודל, סיבוב האצבעות מסובב, והזזתן מזיזה; כשמרימים אצבע אחת, השנייה ממשיכה לגרור בלי קפיצה. במחשב צביטה במשטח המגע (ctrl + גלגלת) משנה גודל. הגבולות זהים לפקדים: 60%–500% ו־90° לכל צד. כפתורי ״לפני/אחרי״ והורדת PNG נמצאים על ההדמיה עצמה. `npm run test:studio` בודק את כל אלה מול `/admin/studio` במחשב, ב־390×844 וב־360×640, ומדמה מגע אמיתי בשתי אצבעות (צביטה, סיבוב, הזזה, העברה לאצבע אחת, גבולות, ושהדף לא נגלל).

**שליחת בקשה לאפרת:** כפתור ״שליחת בקשה לאפרת״ בסטודיו פותח טופס קצר: שם (חובה) והערות (רשות). ״שליחה בוואטסאפ לאפרת״ פותח שיחה עם אפרת (`972523894291`, מ־`artists` ב־`src/data/products.ts`) עם הודעה מוכנה: השם, הכלי, הציור, המיקום/גודל/סיבוב, ההערות וקישור שפותח בדיוק את אותה הדמיה. אין צורך לצרף תמונה: הקישור משחזר את ההדמיה במדויק. אם וואטסאפ לא נפתח (למשל בתצוגה מוטמעת שחוסמת חלונות חדשים), אפשר להעתיק את ההודעה ולשלוח לאפרת ידנית. אין שרת: ההודעה נשלחת מהוואטסאפ של הלקוח, והפרטים לא נשמרים באתר.

## הוספת תמונות לסטודיו

הסטודיו מציג רק כלים ואיורים שמופיעים ב־`src/data/catalog.ts`, לא כל קובץ בתיקיות. `scripts/add_asset.py` מכין את התמונה ומוסיף אותה לקטלוג בפקודה אחת (דורש את סביבת ה־Python שמתוארת בהמשך):

```sh
# איור: PNG שקוף נשמר כמו שהוא; צילום או סריקה על נייר בהיר — הרקע מוסר
.venv/bin/python scripts/add_asset.py artwork poppies "פרגים" ~/Downloads/poppies.jpg --detail "פרגים אדומים"

# כלי: צילום של כלי ריק מלמעלה; אזור הקישוט מאליפסה (ברירת מחדל) או ממסכה
.venv/bin/python scripts/add_asset.py vessel cream-bowl "קערת שמנת" ~/Downloads/bowl.jpg --detail "שמנת מנוקד" --ellipse .5,.55,.3,.2
```

- איור: `--crop L,T,R,B` (שברים 0–1), `--rotate 90`, `--method scan|photo` (סריקה או צילום), `--scale`.
- כלי: `--mask mask.png` (לבן באזור הקישוט, באותם ממדים של הצילום), `--material dark` לגלזורה כהה, `--fit pad` כדי לא לחתוך צילום רחב. הסקריפט שומר תצוגת אזור קישוט ב־`/tmp/<id>-area-preview.jpg` — כדאי להסתכל עליה ולכוונן את `--ellipse` עד שהאזור יושב בתוך הכלי.
- `--dry-run` מראה מה ייכתב בלי לשנות את הקטלוג; `--update` מחליף קבצים של פריט קיים (למשל צילום טוב יותר).
- אחרי ההוספה: לבדוק בסטודיו עם `npm run dev`, ואז commit ו־push.

בדיקות הסטודיו מופעלות באמצעות `npm run test:studio` ופועלות מול `/admin/studio`. בדיקות החנות מופעלות באמצעות `npm run test:visual` ומזריקות תמונות בדיקה לדפדפן בלבד; במערכת שאינה macOS ניתן לספק `CHROME_PATH=/path/to/chrome`.

## הכנת נכסים מקומית

בשרת הפיתוח בלבד אפשר לפתוח `/admin` ולהעלות איור שקוף או צילום איור על נייר בהיר ואחיד, וגם צילום כלי בכל יחס תמונה. JPEG/PNG/WebP/GIF/BMP עד 10MB נבדקים לפי חתימת הקובץ וממדים (עד 20 מיליון פיקסלים); פורמטים שאינם ניתנים לפענוח בדפדפן דורשים המרה. צילום כלי ממורכז על רקע אחיד בתוך נגזרת PNG ביחס 3:4 ללא מתיחה; אפשר להעלות מסכת קישוט תואמת לממדי המקור (לבן בפנים ושחור בחוץ), או ליצור אליפסה משוערת ולכוון את האזור בעזרת הפקדים. לאיור אטום מנסים להסיר רקע נייר בהיר לפי צבע הפינות; רקע מורכב נדחה עם הסבר במקום להציג תוצאה מטעה. המקור במחשב אינו משתנה. הטיוטות נשמרות ב־IndexedDB בדפדפן שבו הועלו, וניתן לבדוק אותן בהדמיה, לרענן את הדף או למחוק אותן.

עיבוד אוטומטי **אינו תומך באופן אמין בכל תמונה**: צבעי מים בהירים, נייר עם כתמים, צילום עם מסגרת/השתקפויות, כלי שאינו מצולם ממול ומסכות אליפטיות עלולים לאבד מידע או להניח אזור קישוט שגוי. חובה להשוות את הנגזרת למקור ולכוון או להכין ידנית לפני שימוש מסחרי.

זו **לא** מערכת Admin לפרסום: אין אימות, שרת או אחסון משותף; הנכסים אינם זמינים ללקוחות ואינם משנים את הקטלוג. מיקומי בדיקת הכלי זמניים ואינם כיול למסכת בטיחות או למידות פיזיות. לפני פריסה של מערכת העלאות אמיתית יש להוסיף שרת מאומת, אחסון פרטי, תהליך אישור וגרסאות נכסים. בדיקת העלאות: להפעיל `npm run dev` ובטרמינל אחר `npm run test:admin` (אפשר להגדיר `POC_URL` לפורט אחר).

## מבנה האתר

עמוד הלקוחות: פתיח, ״רגע של חיבור״, הקולקציה (רק מוצרים עם צילומים מוגמרים ב־`finishedVariants`), צפייה במוצר שנפתחת בלחיצה על כרטיס **מתחת לקולקציה** (כפתורי רדיו לחומר חלק/מנוקד ורשימת הציורים הזמינים, והצילום הנבחר מופיע באותו מסגרת), גלריית ציורים בהשראת שירי מאיר אריאל, עגלה והזמנה בוואטסאפ, ״כדאי לדעת לפני שמזמינים״ ופרטי קשר. הסטודיו אינו מוצג ללקוחות — הוא חי בעמוד הניהול `/admin/studio`.

- `public/assets/hero.webp`: תצלום הפתיחה של האתר (המקור: `landing-hero.jpeg` בשורש הפרויקט, מחוץ ל־git).
- `public/assets/artists.webp`: תצלום האמניות (המקור: `אפרת ועירית.png` בשורש הפרויקט, מחוץ ל־git); אינו מוצג כרגע באתר, נשמר לשימוש עתידי.
- `public/assets/brochure/`: חיתוכי תמונות מתוך דפי החוברת שסופקו (`scripts/prepare_brochure.py`). אלו תמונות המחשה בלבד ואינן מפורסמות בקולקציה; הן משמשות את בדיקות החנות.
- `public/assets/gallery/`: ציורי הגלריה (`gallery-NN.webp` לפי הסדר האלפביתי בתיקיית המקור), מיובאים מ־`assets-source/נישאים ברוח` עם `scripts/import_gallery.py`. אחרי הוספה או החלפת תמונות יש להריץ את הסקריפט מחדש ולעדכן את רשימת `galleryImages` ב־`src/data/gallery.ts` בהתאמה.
- `src/data/products.ts`: מוצרי הקולקציה, מחירים, שילובים מצולמים (`finishedVariants`) ופרטי היוצרות.
- `src/components/Studio.tsx`: הקונפיגורטור; `src/admin/StudioPage.tsx`: עמוד הניהול שעוטף אותו; `src/App.tsx`: אתר הלקוחות.

- `scripts/prepare_assets.py`: חיתוכים, alpha לפי צבע/בהירות, ניקוי לבן קרוב ומסכות כלי. קובצי JPEG המקוריים בשורש אינם משתנים.
- `src/data/catalog.ts`: נתוני הכלים והאיורים, פריסטים נפרדים לכל כלי, פרמטרי עקמומיות, עומק וגימור, ומזהה גרסת נכסים.

### נכסי בדיקה חיצוניים — הוסרו

כל נכסי הבדיקה החיצוניים הוסרו מהסטודיו: שלוש צלחות ה־AI (`ai-round-plate`, `ai-oval-plate`, `ai-rect-platter`), ארבעת איורי ה־AI (`ai-anemones`, `ai-blue-sprig`, `ai-poppies`, `ai-lavender`) ושלושת איורי Mary Vaux Walcott מ־Wikimedia Commons (`monkey-flower`, `gentian`, `poppy`). בקטלוג נותרו רק הכלים האמיתיים של היוצרות וארבעת האיורים המקוריים (`meadow`, `spring`, `garden`, `wildflowers`). המקורות נשמרים ב־`assets-source/ai/` וב־`assets-source/external/`, ו־`scripts/fetch_test_assets.py` נשאר כלי להורדה מ־Wikimedia Commons. `rim-bowl.jpg` עדיין נחוץ לבדיקת ה־Admin.

אם נדרש לייצר שוב את הנכסים על Mac/Linux עם Python 3.13:

```sh
python3 -m venv .venv
.venv/bin/pip install pillow==11.3.0 numpy==2.2.6 opencv-python-headless==4.11.0.86
.venv/bin/python scripts/prepare_assets.py
```

הרינדור נקבע אך ורק על פי צילום כלי ומסכה, PNG שקוף, פריסט וגרסת הנכסים/קוד. שינוי בקובצי המקור או במנוע מחייב לעדכן את `assetVersion` בקטלוג אם משתמשים במפתח השחזור להשוואה בין גרסאות.

## הערכת איכות בעקבות בדיקת שילובים

| שילוב | הערכה |
|---|---|
| תכלת + פרחי שדה | הקריא והמשכנע ביותר ביחס לחומרים הזמינים; צמחייה, גוונים ושקיפות משתלבים יחסית היטב בגלזורה. |
| תכלת + פריחת אביב | קריא אך ציור צפוף יותר; הקטנת הפריסט נותנת תוצאה רגועה יותר. |
| תכלת + פריחת גן | קומפוזיציה שלישית שימושית לבחינת התאמה וצבע מתוך אותו ציור, לא יצירת מקור עצמאית. |
| תכלת + לבנדר פראי | פחות מוצלח: הפרחים הלבנים כמעט נעלמים בהפרדת רקע נייר, ונשאר בעיקר ענף כהה. |
| כחול + שלוש קומפוזיציות מציור השדה | האיור נראה בקושי עד בינוני, בהתאם לגוון; הטשטוש וההשתקפות המקורית מקשים לשפוט תוצאה פיזית. |
| כחול + לבנדר פראי | כמעט בלתי נראה; אינו שילוב אמין להצעה מסחרית בלי ניסוי פיזי וציור מקור נקי. |

כל שמונת השילובים נבדקו בפועל ב־Chrome. בדיקה אוטומטית השוותה תמונת ״לפני״ ל״אחרי״, ווידאה ששינויים בצבע מופיעים רק בתחומי מסכת הכלי וששחזור הגדרה זהה מחזיר תמונה זהה. `validation/` מכילה צילומי מסך, כולל דוגמת מובייל.

**מגבלות מהותיות:** האיור הממוסגר מצולם מאחורי זכוכית, עם השתקפויות ופרחים לבנים על נייר לבן; alpha אוטומטי אינו יכול לשחזר פיגמנט לבן שאינו נבדל מהרקע. בקערה התכולה הרקע העצי וההשתקפויות המקוריות נשארים כחלק מהצילום; בשתיהן מסכת המשטח מקורבת ולא חופפת בוודאות לכל דופן פנימית. העיוות המרוצף מעניק רמז לקימור אבל אינו כיול פרספקטיבה או מפת displacement פיזיקלית. ערבוב על הקערה הכחולה מכוון להיות שמרני: הגברת צבע מלאכותית הייתה מספקת preview מרשים אך עלולה להטעות. הצילומים הנוכחיים **מספיקים לבחינת כיוון, לא להדמיית מוצר אמינה לפרסום או להזמנה**.

**לגרסת ייצור נדרשים:** סריקה או ייצוא מקורי של כל איור בשקיפות אמיתית וברזולוציה גבוהה; צילומי קערות ריקות בתאורה מפוזרת קבועה, ללא רקע מסיח ובזווית ידועה; מסכות מדויקות לכל צילום וגימור; מידות פיזיות של אזור קישוט; תמונות אמת של קערות מאוירות להשוואת פרופיל צבע והצללה; בדיקת פיגמנט על גלזורה כחולה. לכלים קעורים יותר, לבחון מפת עיוות מכוילת לכלי במקום עיקום גנרי. אם איסוף הנכסים אינו אפשרי, אין להציג את ההדמיה כצילום צפוי של המוצר.
